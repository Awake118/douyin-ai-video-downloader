# 画质档位：怎么判断拿到的到底是不是最高画质

## 档位从哪来

详情 API（`aweme/v1/web/aweme/detail/`）响应里的 `aweme_detail.video` 字段：

| 字段 | 含义 |
|---|---|
| `bit_rate[]` | **全部可用档位**，每个元素含 `gear_name`、`bit_rate`、`quality_type`、`play_addr`（含 `width`/`height`/`data_size`） |
| `play_addr` | 播放器默认地址，通常等于最高档（用 `data_size` 可核对） |
| `play_addr_h264` / `play_addr_265` | 指定编码的地址，`265` 那路分辨率往往**更低** |
| `download_addr` | 兜底下载地址，档位通常更低，仅在前两者都取不到时使用 |

档位命名：`normal_720_0` / `low_720_0` / `adapt_540_1` / `adapt_lowest_720_1` …… 前缀是策略（normal/low/adapt），
中间是目标高度，末尾是质量档序号。抖音 UI 的对应关系大致是：

| 抖音的叫法 | 档位前缀 | 分辨率 |
|---|---|---|
| 标清 | `*_540_*` | 1024×576 |
| 高清 | `*_720_*` | 1280×720 |
| （登录后部分作品） | `*_1080_*` | 1920×1080 |

## 挑选规则（`scripts/get_video.sh` 内置）

1. `source=api` 的候选（详情 API 的 `play_addr` / `bit_rate`）优先于播放器抓包候选
2. 同源内按 `note` 里的 `kbps` **降序**取最高档
3. 若最高档不足 720p（< 1400 kbps），**再抓一次**并合并候选后重挑

## 判断上限：一个完整案例

一条 AI 生成的短剧作品，**未登录**抓取得到 19 条候选，**登录后**抓取得到 15 个档位，两次的档位表**完全相同**：

| gear_name | 码率 | 分辨率 | data_size |
|---|---|---|---|
| **normal_720_0** | **1719 kbps** | **1280×720** | **161,878,274** |
| normal_720_0 | 1217 kbps | 1280×720 | 114,653,073 |
| normal_540_0 | 1206 kbps | 1024×576 | 113,566,571 |
| low_720_0 | 1096 kbps | 1280×720 | 103,267,634 |
| low_540_0 | 984 kbps | 1024×576 | 92,713,385 |
| adapt_lowest_720_1 | 770 kbps | 1280×720 | 72,499,885 |
| adapt_540_1 | 727 kbps | 1024×576 | 68,540,552 |
| …（共 15 档） | 455–1096 kbps | 1024×576 / 1280×720 | 更小 |

**没有 1080p 档位**。判定"已拿到最高画质"的硬证据：

```
play_addr.data_size            = 161,878,274
最高档 normal_720_0.data_size   = 161,878,274
实际下载文件字节数               = 161,878,274   ← 三者完全一致
```

顺带查了这条作品的付费标记：`series_paid_info.item_price = 0`、`series_paid_status = 0`、
`entertainment_video_paid_way.paid_type = 0`，属于免费短剧，不存在"会员才给高清"的门槛。

所以：**该作品服务端存在的最高画质就是 1280×720 / 1719 kbps**，用户觉得"是标清"属于观感问题
（AI 生成内容本身偏软 + 720p 全屏放大），不是下载器挑错了。

## 排查清单：用户说"画质不对"时

1. 看抓取输出里的档位表，确认脚本选的是不是最高档
2. 对比 `play_addr.data_size` 与实际文件字节数——**一致就说明拿到的是服务端最优的一份**
3. 确认作品本身有没有更高档位：`bit_rate` 里没有 `1080`，那就是没有
4. 只有在档位表里确实存在更高档、但当前拿不到时，才去怀疑登录态

## 登录到底改变了什么

未登录时抖音网页端**不给 1080p 档位**；登录后部分作品会多出 1080p 档。但：

- 登录**不会**凭空创造更高分辨率——源头没有就是没有
- 登录态只在 `.chrome-profile` 里，过期后重跑 `scripts/login.sh` 即可
- headless + 已登录账号更容易触发风控（实测：登录后 headless 抓取卡在"视频数据加载中"，
  换成有窗口模式立刻恢复）

## 其他坑

- **DASH 分轨**：网页播放器会分别请求 `media-video-*`（纯视频）和 `media-audio-*`（纯音频）。
  没有 ffmpeg 合并的话拿到的是无声视频——所以脚本优先取含音视频的整段 mp4（`tos-cn-ve-*`）
- **HEVC 更小不等于更好**：`play_addr_265` 常见是 1024×576，比 720p 档更低
- **`download_addr` 只是兜底**：档位通常更低，优先用 `play_addr` / `bit_rate`
